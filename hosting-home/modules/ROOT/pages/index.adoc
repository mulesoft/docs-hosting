= Anypoint Platform Hosting Overview
:page-aliases: general::intro-platform-hosting.adoc

Host the Anypoint Platform control plane and runtime plane in different locations to meet your security, data privacy, and compliance requirements. Choose from MuleSoft-managed cloud options or self-hosted environments to control where your data is stored and processed. The control plane location, runtime hosting option, and runtime region are independent choices.

== Control Plane and Runtime Plane

Anypoint Platform architecture separates into two distinct planes that can be hosted independently:

image:intro-control-runtime-planes.png[Diagram of contents of the control plane and runtime plane]

Control plane::
The management layer of Anypoint Platform, where you design, deploy, and manage APIs and Mule apps. Your organization, identity, and design-time metadata live in this plane.

Runtime plane::
The components where your APIs and Mule applications are deployed and made available to your users. The runtime plane includes the Mule runtime engine and supporting services.

== Choosing a Hosting Option

Anypoint Platform lets you host the control plane and runtime plane independently. MuleSoft names each regional MuleSoft-managed control plane a cloud, for example US Cloud or EU Cloud. Each Anypoint Platform organization lives in exactly one cloud. Choose a cloud (where design-time data and metadata live) and a runtime option (who runs your applications and on what infrastructure). If you use CloudHub or CloudHub 2.0, also choose a runtime region (where those applications execute). After you choose a commercial cloud, see xref:control-planes::index.adoc[Anypoint Platform Control Planes Overview] to sign in, create, and deploy.

Depending on your requirements, you can choose from these options:

* Use Anypoint Platform in the MuleSoft-managed control plane and runtime plane.
* Host and manage the runtime plane within your own infrastructure while connecting it with the MuleSoft-managed control plane.
* Host both the control plane and runtime plane locally within your infrastructure.

These sections list the available options. Use <<support-matrix-control-plane>> to confirm which combinations are supported. After you choose a runtime option, see xref:hadr-guide.adoc[High Availability and Disaster Recovery Across Deployment Models] for how each model stays available and who owns failover.

== Runtime Plane Hosting Options

MuleSoft provides different options for hosting the runtime plane:

[%header%autowidth.spread,cols="2,3,2"]
|===
| Runtime Option | Description | Managed By

| xref:cloudhub-2::index.adoc[CloudHub 2.0]
| Fully managed, containerized integration platform as a service (iPaaS) for running APIs and integrations as lightweight containers in the cloud. Supports auto-scaling, high availability, and dynamic infrastructure across the runtime regions available in your control plane.
| MuleSoft

| xref:runtime-manager::cloudhub.adoc[CloudHub]
| Cloud-based environment for running Mule applications in the cloud. Supports high availability, clustering, failover, and load balancing.
| MuleSoft

| xref:runtime-fabric::index.adoc[Runtime Fabric]
| Container service for running Mule applications and API gateways in your data center or third-party cloud. Supports high availability, failover, clustering, and load balancing with bundled Docker and Kubernetes.
| Customer (infrastructure) and MuleSoft (orchestration)

| xref:hybrid-standalone::index.adoc[Hybrid Standalone Runtimes]
| Mule runtime engine for running applications in your environment (physical server, virtual machine (VM), or cloud such as AWS or Azure). Supports centralized management through the MuleSoft control plane while keeping deployments within your trust boundary.
| Customer (infrastructure) and MuleSoft (management)

| xref:mule-runtime::mule-standalone.adoc[On-Premises Runtimes]
| Mule runtime engine for running applications on a single instance with no required connection to the control plane. Requires you to manage high availability, failover, clustering, and load balancing, and is suited for air-gapped or disconnected environments.
| Customer (fully self-managed)
|===

If you use CloudHub or CloudHub 2.0, you also choose a runtime region: the geographic location where those applications execute. A runtime region is independent of control plane data residency. For example, deploying to Canada (Montreal) from US Cloud does not give you Canada Cloud. Runtime Fabric, Hybrid Standalone, and On-Premises runtimes run in your infrastructure and don't use MuleSoft-managed runtime regions.

For CloudHub 2.0 regions, identifiers, and DNS records, see xref:cloudhub-2::ch2-architecture.adoc#regions-and-dns-records[Runtime Plane Regions and DNS Records].
