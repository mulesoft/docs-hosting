= Anypoint Platform Hosting Overview
:page-aliases: general::intro-platform-hosting.adoc

Host the Anypoint Platform control plane and runtime plane in different locations to meet your security, data privacy, and compliance requirements. Choose from MuleSoft-managed cloud options or self-hosted environments to control where your data is stored and processed. Each option keeps your data within the physical location your organization requires.

== Control Plane and Runtime Plane

Anypoint Platform architecture separates into two distinct planes that can be hosted independently:

image:intro-control-runtime-planes.png[Diagram of contents of the control plane and runtime plane]

Control plane::
The components you use to design, deploy, and manage APIs and Mule applications. The control plane includes Anypoint Design Center, Anypoint Management Center, and Anypoint Exchange.

Runtime plane::
The components where your APIs and Mule applications are deployed and made available to your users. The runtime plane includes the Mule runtime engine and supporting services.

== Runtime Plane Hosting Options

MuleSoft provides different options for hosting the runtime plane:

[%header%autowidth.spread,cols="2,3,2,2"]
|===
| Runtime Option | Description | Managed By | Key Characteristics

| CloudHub 2.0
| Fully managed, containerized integration platform as a service (iPaaS) for deploying APIs and integrations as lightweight containers in the cloud. Supports deployments across 12 regions globally with single or shared tenancy.
| MuleSoft
| Auto-scaling, high availability, dynamic infrastructure. See xref:cloudhub-2::index.adoc[CloudHub 2.0].

| CloudHub
| MuleSoft's cloud-based environment for hosting Mule runtime. Provides high availability, clustering, failover, and load balancing.
| MuleSoft
| See xref:runtime-manager::cloudhub.adoc[CloudHub].

| Runtime Fabric
| Container service for running Mule applications and API gateways in your own data center or third-party cloud. Bundled with Docker and Kubernetes for high availability, failover, clustering, and load balancing.
| Customer (infrastructure) and MuleSoft (orchestration)
| See xref:runtime-fabric::index.adoc[Anypoint Runtime Fabric].

| Hybrid Standalone Runtimes
| Mule runtime engine hosted in your environment (physical server, virtual machine (VM), or cloud like AWS/Azure) with centralized management through the MuleSoft control plane.
| Customer (infrastructure) and MuleSoft (management)
| Deployments within your trust boundary with cloud-based centralized management. See xref:hybrid-standalone::index.adoc[Hybrid Standalone].

| Standalone Runtimes
| Mule runtime engine on a single instance with no required connection to the control plane. You manage high availability (HA), failover, clustering, and load balancing manually. Suited for air-gapped or disconnected environments.
| Customer (fully self-managed)
| See xref:mule-runtime::mule-standalone.adoc[Run Mule Runtime Engine On-Premises].
|===

[[support-matrix-runtime]]
=== Component Support by Runtime Option

Not all Anypoint Platform components are available in each runtime option:

[%header%autowidth.spread]
|===
| Component | CloudHub 2.0 | CloudHub | Runtime Fabric | Standalone

| Mule runtime engine | Yes | Yes | Yes | Yes
| Anypoint MQ | Yes | Yes | Yes | Yes
| Anypoint Object Store v2 | Yes | Yes | No ^1^ | No ^1^
| Anypoint DataGraph | No | Yes | No | No
| Connectors ^2^ | Yes | Yes | Yes | Yes
|===

^1^ Runtime Fabric and standalone runtimes support Mule clustering instead of Object Store v2. On Runtime Fabric, multiple replicas of the same application can share objects. See xref:mule-runtime::choosing-the-right-clustering-topology.adoc[Cluster Runtime Instances]. +
^2^ File system connectors (for example, Anypoint Connector for File) are not supported on Runtime Fabric because deployed apps lack file system access.

== Choosing a Hosting Option

Anypoint Platform lets you host the control plane and runtime plane independently. Depending on your requirements, you can choose from these options:

* Use Anypoint Platform in the MuleSoft-managed control plane and runtime plane.
* Host and manage the runtime plane within your own infrastructure while connecting it with the MuleSoft-managed control plane.
* Host both the control plane and runtime plane locally within your infrastructure.

See the <<Control Plane Hosting Options>> and <<Runtime Plane Hosting Options>> tables for available options, and the <<support-matrix-control-plane>> to verify which combinations are supported.
