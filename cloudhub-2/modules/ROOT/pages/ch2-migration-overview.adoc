Migrate CloudHub applications and infrastructure to CloudHub 2.0. Review the platform differences, choose a migration path, and complete each step in order.

== Migration Journey Overview

Migrate from CloudHub to CloudHub 2.0 in these five steps.

. xref:ch2-migration-plan.adoc[]. Audit apps, assess entitlements, estimate timelines, and choose a migration strategy.
. xref:ch2-migration-infrastructure.adoc[]. Create a private space or upgrade an eligible VPC, then configure network connectivity.
. xref:ch2-migration-apps.adoc[]. Update app code, deploy to CloudHub 2.0, and configure app properties.
. xref:ch2-migration-validate.adoc[]. Switch traffic gradually, monitor for issues, and complete DNS cutover.
. xref:ch2-migration-finalize.adoc[]. Decommission CloudHub resources and release entitlements.

== Choose Your Migration Path

Choose the path that fits your infrastructure.

* Create a new private space if your VPC doesn't meet upgrade eligibility requirements or if CloudHub 2.0 needs a different CIDR block.
* Upgrade your VPC to a private space if it meets the eligibility requirements and you need to retain the existing CIDR block and infrastructure configuration.

For eligibility criteria and help choosing a migration path, see xref:ch2-migration-plan.adoc#determine-your-migration-path[]. For setup procedures for each path, see xref:ch2-migration-infrastructure.adoc[].

== Assess Migration Impacts

Before planning your migration, review the differences that can require infrastructure or application changes.

* Infrastructure and networking: private spaces, connectivity, firewall rules, static IP addresses, load balancing, domains, and TLS.
* Traffic routing: DLB mapping rules, ingress endpoints and paths, certificates, access-control rules, and traffic switching behavior.
* App deployment: Mule runtime compatibility, deployment configuration, app properties, worker-to-replica sizing, clustering, and alerts.
* App behavior: persistent VM queues, logging, internal app communication, injected HTTP headers, and connection timeout behavior.

For the complete CloudHub and CloudHub 2.0 comparison, including DLB-to-ingress migration considerations, see xref:ch2-migration-comparison.adoc[].
