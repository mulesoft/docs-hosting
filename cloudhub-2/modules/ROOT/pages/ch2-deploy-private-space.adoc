--
TLS Options::
+
--

* *Forward SSL Session*
+
Enables SSL forwarding during a session.
+
SSL forwarding is mostly used with client authentication.
See xref:anypoint-security::enable-client-authentication.adoc[].
SSL forwarding forwards client certificate details in HTTP request headers so they are available to the application.
These fields can identify an authenticated client and allow an application to determine and use the identity.
+
The following headers are available:
+
[%header,cols="2*a"]
|===
| Header Name | Value
| x-ssl-client-verify | SUCCESS/FAIL
| x-ssl-issuer | Client certificate issuer
| x-ssl-client-serial | Client certificate serial number. The format differs by control plane. See <<ingress-behavior-by-control-plane>>.
| x-ssl-client-dn | Contents of the client certificate DN field
| x-ssl-client-cert | Contents of the client certificate
|===

* *Last-Mile Security*
+
Specifies that TLS termination and decryption for the forwarded HTTPS connections occurs in the application.
+
This option requires that the Mule application include an SSL certificate and also requires more CPU resources.
--

[[ingress-behavior-by-control-plane]]
== Ingress Behavior Differences by Control Plane

India Cloud, Australia Cloud, United Kingdom Cloud, Brazil Cloud, and control planes added after them use a different ingress controller. US Cloud, EU Cloud, Canada Cloud, and Japan Cloud use the original ingress controller. The same CloudHub 2.0 features are available on every control plane. HTTP header handling and path rewrite differ.

If you move an app to India Cloud, Australia Cloud, United Kingdom Cloud, Brazil Cloud, or a control plane added after them, review this behavior before you switch traffic.

=== HTTP Header Handling

`x-forwarded-host`::
On India Cloud, Australia Cloud, United Kingdom Cloud, Brazil Cloud, and control planes added after them, the ingress controller passes the client `Host` header to the app unchanged and doesn't send `x-forwarded-host`.
+
On US Cloud, EU Cloud, Canada Cloud, and Japan Cloud, the ingress controller removes the original host and sends that value in `x-forwarded-host`.
+
If the app reads `x-forwarded-host`, update it to read the `Host` header.

`x-correlation-id`::
On US Cloud, EU Cloud, Canada Cloud, and Japan Cloud, the ingress controller creates an `x-correlation-id` value when the client doesn't send one.
+
On India Cloud, Australia Cloud, United Kingdom Cloud, Brazil Cloud, and control planes added after them, the ingress controller forwards `x-correlation-id` only when the client sends it.
+
If tracing depends on a correlation ID from the ingress controller, send `x-correlation-id` from the client or create the ID in the app.

`x-ssl-client-serial`::
When *Forward SSL Session* is enabled, the ingress controller sends the client certificate serial number in `x-ssl-client-serial`.
+
On US Cloud, EU Cloud, Canada Cloud, and Japan Cloud, the value is a decimal integer.
+
On India Cloud, Australia Cloud, United Kingdom Cloud, Brazil Cloud, and control planes added after them, the value is a hexadecimal string. That string matches the serial number shown by certificate tools such as OpenSSL.
+
If the app reads this header, parse a hexadecimal string on those control planes.

=== Path Rewrite

_Path_ is the path clients request. _Path Rewrite_ is the path the HTTP listener in the app expects. A trailing slash is part of the path, so set _Path_ and _Path Rewrite_ to match the public URL and the application endpoint, including the slash.
