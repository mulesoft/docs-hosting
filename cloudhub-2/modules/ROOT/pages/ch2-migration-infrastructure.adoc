Before migrating applications, set up your CloudHub 2.0 infrastructure. Choose between creating a new private space manually or using the VPC upgrade tool to convert an existing VPC to a private space.

== Choose Your Path

Choose a path based on whether your VPC meets the upgrade eligibility requirements.

[cols="1,2,2"]
|===
|Path |Use When |What Happens

|xref:ch2-migration-infrastructure-new-space.adoc[Create a New Private Space Manually]
|Your VPC doesn't meet upgrade eligibility requirements, or you need CloudHub 2.0 on a different CIDR from your existing VPC.
|You create a new private space from scratch with its own CIDR block, configure network connections, and set up firewall rules independently.

|xref:ch2-migration-infrastructure-vpc-upgrade.adoc[Upgrade a VPC to a Private Space]
|Your VPC meets all xref:cloudhub::vpc-upgrade.adoc#understand-eligibility[eligibility requirements] and you want to retain your existing infrastructure configuration.
|The upgrade tool clones your VPC configuration (CIDR block, firewall rules, VPN/TGW connections, DLB certificates) into a new CloudHub 2.0 private space.
|===

== Review Infrastructure Considerations

Whichever path you choose, review how DLB features map to CloudHub 2.0 ingress, how CloudHub and CloudHub 2.0 applications communicate, how static IPs change, and how to maintain business continuity. See xref:ch2-migration-infrastructure-considerations.adoc[Infrastructure Considerations for Migration].
