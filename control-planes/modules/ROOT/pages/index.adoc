= Anypoint Platform Control Planes Overview
:page-aliases: eu-control-plane::index.adoc, eu-control-plane::object-store-eu.adoc, anypoint-clouds::index.adoc, accessing-control-planes.adoc, eu-control-plane::platform-access-eu.adoc, eu-control-plane::studio-platform-access-eu.adoc, accessing-anypoint-clouds.adoc, anypoint-clouds::accessing-anypoint-clouds.adoc

Anypoint Platform control planes are the MuleSoft-managed environments where you design, deploy, and manage APIs and Mule apps. Each Anypoint Platform organization lives in exactly one control plane. Sign in to that control plane and deploy Mule apps to the runtime planes it supports.

For the full catalog of control planes (including MuleSoft Government Cloud and Anypoint Platform Private Cloud Edition (PCE)) and the control plane and runtime compatibility matrix, see xref:hosting-home::index.adoc[Anypoint Platform Hosting Overview].

== Control Plane Clouds

MuleSoft hosts a control plane in each supported geography and names that regional control plane a cloud, for example US Cloud or EU Cloud. US Cloud is the US control plane. EU Cloud is the EU control plane. **Cloud** is the product name of that isolated Anypoint Platform instance (login URL, organization, and data residency). **Control plane** is the management layer in that instance, as distinct from the xref:hosting-home::index.adoc#control-plane-and-runtime-plane[runtime plane], where apps run.

You choose one cloud for your organization. You do not choose a cloud and a control plane as two separate products.

If MuleSoft hosts your runtime (CloudHub or CloudHub 2.0), continue with xref:creating-and-deploying-mule-apps.adoc[Creating and Deploying Mule Apps]. xref:finding-endpoints-allowlists.adoc[Finding Endpoints and Allowlists] and xref:configuring-mule-control-planes.adoc[Configuring Mule to Access Anypoint Platform Control Planes] apply when you host Mule or need API gateway on a non-US Cloud.

For data residency and compliance notes for each control plane, see xref:hosting-home::index.adoc#control-plane-hosting-options[Control Plane Hosting Options].

== Signing In to the Control Plane

Sign in to the Anypoint Platform control plane that holds your organization. Use the platform URL for that cloud. Organizations and user accounts are not shared across clouds. MuleSoft adds new regional clouds over time.

. Go to the platform URL for your cloud:
+
[%header%autowidth.spread]
|===
| Cloud | Platform URL

| US Cloud (default)
| https://anypoint.mulesoft.com[`anypoint.mulesoft.com`]

| EU Cloud
| https://eu1.anypoint.mulesoft.com[`eu1.anypoint.mulesoft.com`]

| Canada Cloud
| https://ca1.platform.mulesoft.com[`ca1.platform.mulesoft.com`]

| Japan Cloud
| https://jp1.platform.mulesoft.com[`jp1.platform.mulesoft.com`]

| India Cloud
| https://in1.platform.mulesoft.com[`in1.platform.mulesoft.com`]

| Australia Cloud
| https://au1.platform.mulesoft.com[`au1.platform.mulesoft.com`]
|===

. If you do not have an account in that cloud, click *Sign Up* and create one.
. Enter your username and password, then click *Sign In*.

To sign in from a tool outside the platform UI, point that tool at the same control plane:

* xref:studio::hyperforce-configuration.adoc[Configure Anypoint Studio for Control Planes]
* xref:anypoint-code-builder::start-acb.adoc#change-clouds[Set the Desktop IDE to a Different Control Plane]
* xref:anypoint-cli::index.adoc#default-options[Anypoint CLI] `--host` flag or `ANYPOINT_HOST` (defaults to US Cloud)

The Anypoint Code Builder desktop IDE control-plane picker lists US Cloud, EU Cloud, Canada Cloud, and Japan Cloud.

Configuring Mule (`wrapper.conf` or `base_uri`) is a separate job for a running Mule instance. It is not required to sign in. See xref:configuring-mule-control-planes.adoc[Configuring Mule to Access Anypoint Platform Control Planes].
