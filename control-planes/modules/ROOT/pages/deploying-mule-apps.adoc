= Deploying Mule Apps
:page-aliases: hyperforce::deploy-mule-apps-hyperforce.adoc, eu-control-plane::app-deploy-eu.adoc, anypoint-clouds::deploying-mule-apps.adoc

[[deploy-mule-apps-to-control-planes]]
Deploy Mule apps from the Anypoint Platform control plane that holds your organization. Which runtime plane you can use depends on that control plane. Follow the product deploy topic for CloudHub, CloudHub 2.0, Runtime Fabric, or Hybrid Standalone.

== Prepare the Control Plane

. Sign in to the control plane that holds the organization. See xref:accessing-control-planes.adoc[Accessing Anypoint Platform Control Planes].
. If the control plane is not US Cloud, point Mule, Anypoint Studio, Anypoint Code Builder, or Maven at that control plane:
+
* xref:configuring-mule-control-planes.adoc[Configuring Mule to Access Anypoint Platform Control Planes]
* xref:studio::hyperforce-configuration.adoc[Configure Anypoint Studio for Control Planes]
* xref:anypoint-code-builder::start-acb.adoc#change-clouds[Configure Anypoint Code Builder to a Different Control Plane]
* xref:exchange::to-publish-assets-maven.adoc#publish-an-asset-to-exchange-using-maven[Publish an Asset to Exchange Using Maven]

== Choose a Runtime Plane

See the xref:hosting-home::index.adoc#support-matrix-control-plane[control plane and runtime plane compatibility matrix], then follow the product topic for that runtime:

[%header%autowidth.spread]
|===
| Runtime plane | Control Planes | Where to deploy

| CloudHub 2.0
a|
* US Cloud
* EU Cloud
* Canada Cloud
* Japan Cloud
* India Cloud
* Australia Cloud
| xref:cloudhub-2::ch2-deploy.adoc[Deploying Apps to CloudHub 2.0]. For DNS and URL format, see xref:cloudhub-2::ch2-architecture.adoc#regions-and-dns-records[Runtime Plane Regions and DNS Records].

| CloudHub
a|
* US Cloud
* EU Cloud
| xref:runtime-manager::deploying-to-cloudhub.adoc[Deploying to CloudHub].

| Runtime Fabric
a|
* US Cloud
* EU Cloud
* Canada Cloud
* Japan Cloud
* India Cloud
* Australia Cloud
| xref:runtime-fabric::deploy-index.adoc[Deploying Mule Apps to Runtime Fabric]. For Canada Cloud, Japan Cloud, India Cloud, and Australia Cloud, contact your account manager to unlock Runtime Fabric.

| Hybrid Standalone
a|
* US Cloud
* EU Cloud
* Canada Cloud
* Japan Cloud
* India Cloud
* Australia Cloud
| xref:hybrid-standalone::deploying-apps-hybrid-standalone.adoc[Deploying Mule Apps to Hybrid Standalone Instances]. Register the Runtime Manager agent with the control plane that holds the organization. A Mule instance that is not registered to Runtime Manager is an on-premises runtime, not a control-plane deploy. See xref:mule-runtime::mule-standalone.adoc[Run Mule Runtime Engine On-Premises].
|===
